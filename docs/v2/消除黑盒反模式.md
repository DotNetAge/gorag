# 消除黑盒反模式

## 问题

在 Chunk 与 Node 之中的 Meta 与 Properties 属性由于可以随意读写，在代码中存在黑盒反模式。导致存在于 Meta 或 Properties 之中与处理逻辑相关的一些重要属性的名称散落、设置值被隐藏，代码难以维护。

### 典型黑盒场景

**1. 序列化/反序列化键名散落**

`buildVectorMetadata` 写入 `m["content"]`、`m["title"]`、`m["doc_id"]` 等键，`vectorToChunk` 读取 `vec.Metadata["content"]`、`vec.Metadata["title"]` 等键。两处键名完全靠人工对齐，改一处忘另一处就会丢数据。

**2. 跨包隐式约定**

chunker 写入 `Metadata["language"]`、`Metadata["source"]`，indexer 读取这些键——跨包约定只靠注释说明，没有编译器检查。

**3. 类型断言散落**

到处都是 `v.Metadata["xxx"].(string)` 这种模式，类型不安全，断言失败时静默返回零值。

## 基础方案（原提案）

1. 对于 Meta 与 Properties 不可以直接读写，而应该通过 `Extend([]map[string]any{})` 方法来扩展，这个方法与 JQuery 中经典 `$.extend()` 方法类似，用于合并或覆盖属性值。
2. 将写入 Meta 与 Properties 的内容统一分析提取出常用值，常用结构将其结构化与具名化，方便后续维护。
3. 只对于可变型的属性才直接写入。

## 对基础方案的评价

### 方案1（Extend 方法）价值有限

```go
// 现在的写法
chunk.Metadata["language"] = "go"

// Extend 方法后
chunk.Extend(map[string]any{"language": "go"})
```

只是换了语法糖，键名 `"language"` 仍然散落，类型仍然 `any`，黑盒还是黑盒。而且 Extend 只解决"写"，不解决"读"——读取时仍然是 `m["language"].(string)`。

### 方案1与方案3自相矛盾

方案1说"不可以直接读写"，方案3说"只对可变型属性直接写入"。到底什么时候用 Extend、什么时候直接写？边界模糊。

### 方案2（具名化）才是正解，但未展开

当前代码已经部分实现了具名化：`Chunk` 有 `Title/Summary/Content/DocID/ParentID` 等具名字段。问题是仍有很多属性（`heading_level`、`start_line`、`language`、`source`、`source_file` 等）堆在 Metadata 里。

## 最终方案：三层分级

核心原则：**让编译器帮你检查键名一致性**，而不是靠人工对齐或 Extend 方法。

### 第一层：高频跨包属性 → 提升为结构体字段

已经提升的：`Title`、`Summary`、`Content`、`DocID`、`ParentID`

还应该提升的：

| 属性      | 键名                     | 写入方       | 读取方              |
| --------- | ------------------------ | ------------ | ------------------- |
| Source    | `source` / `source_file` | chunker      | indexer             |
| RegionID  | `region_id`              | chunker      | indexer / graph     |
| Language  | `language`               | code chunker | formatter / indexer |
| StartLine | `start_line`             | code chunker | formatter           |
| EndLine   | `end_line`               | code chunker | formatter           |

这些属性跨包传递，必须有编译器能检查的具名入口。

### 第二层：中频包内属性 → 常量键名

仍存在 Metadata 中，但键名用常量定义，消除字符串散落：

```go
// core/chunk.go
const (
    MetaHeadingLevel = "heading_level"
    MetaHeadingPath  = "heading_path"
    MetaSymbolType   = "symbol_type"
    MetaSignature    = "signature"
    MetaVisibility   = "visibility"
    MetaReceiver     = "receiver"
    MetaPackage      = "package"
    MetaMimeType     = "mime_type"
    MetaDirectory    = "directory"
)
```

写入：`chunk.Metadata[MetaHeadingLevel] = level`
读取：`level, _ := chunk.Metadata[MetaHeadingLevel].(int)`

键名修改时编译器会报错，不会遗漏。Node.Properties 同理定义 `PropXxx` 常量。

### 第三层：低频可变属性 → 自由写入

真正特定场景才用的属性（如 `tags`、`entity_ids`、`thumbnail_size`），允许直接字符串键写入。这些属性本身就是为了灵活性存在的，不应过度约束。

### 序列化/反序列化集中管理

`buildVectorMetadata` / `vectorToChunk` 这对互逆函数是黑盒最严重的地方，用常量键名 + 集中管理：

```go
// core/vector.go
const (
    VecMetaContent  = "content"
    VecMetaTitle    = "title"
    VecMetaSummary  = "summary"
    VecMetaDocID    = "doc_id"
    VecMetaParentID = "parent_id"
    VecMetaSource   = "source"
)
```

两处函数引用同一组常量，改一处编译器自动报另一处。

## 实施步骤

1. 在 `core/chunk.go` 定义 `Meta*` 常量，在 `core/node.go` 定义 `Prop*` 常量，在 `core/vector.go` 定义 `VecMeta*` 常量
2. 全局替换第一层属性：将散落的 `Metadata["source"]`、`Metadata["region_id"]`、`Metadata["language"]` 等替换为结构体字段读写
3. 全局替换第二层属性：将散落的字符串键名替换为常量引用
4. 第三层属性保持不变
5. 运行 `go build ./...`、`go vet ./...`、`go test ./...` 确保全部通过
